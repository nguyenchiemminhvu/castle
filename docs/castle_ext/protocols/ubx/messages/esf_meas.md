# UBX ESF-MEAS

## Overview

Model of UBX-ESF-MEAS (0x10 0x02), the input/output external-sensor measurement message. The host sends it to feed
wheel ticks or speed into the ZED-F9R fusion filter, so `encode()` is a first-class API; `decode()` handles
receiver output and loop-back. Payload: `8 + numMeas·4 + [0,1]·4`, i.e. a header, `numMeas` 32-bit data words
and an optional calibrated time tag.

**Changes:**
- `calibTtag` is present iff `flags.calibTtagValid` (bit 3). The previous code keyed it on `timeMarkSent`
  (bits 1..0), which is wrong.
- `numMeas` is read from `flags` bits 15..11. When it is non-zero the payload length is validated exactly; when it
  is zero the count is implied by the payload length (the spec marks `numMeas` optional).
- Storage is now a `castle::container::vector`.
- `num_meas` / `has_calib_ttag` members became the `num_meas()` / `calib_ttag_valid()` accessors over `flags`, so
  they can never disagree with the wire.
- `FLAGS_TIME_TAG_TYPE_MASK` / `FLAGS_TIME_MARK_SENT_MASK` (wrong bits) were replaced by spec-named masks.
- The default capacity is now 31, the 5-bit `numMeas` maximum.

## Public API

### Types

| Type | Description |
| --- | --- |
| `esf_meas_datum` | One `data` word: `data_type` (bits 29..24) + `data_value` (bits 23..0, sign-extended). `wire_size = 4`. |
| `esf_meas<MaxData = 31U>` | Message payload; `MaxData` must be in 1..31. |

### Constants

| Name | Value | Meaning |
| --- | --- | --- |
| `msg_class` / `msg_id` | `0x10` / `0x02` | Frame identity. |
| `header_length` / `block_length` / `calib_ttag_length` | `8` / `4` / `4` | Wire sizes. |
| `FLAGS_TIME_MARK_SENT` | `0x0003` | Bits 1..0: `TIME_MARK_NONE` (0), `TIME_MARK_EXT0` (1), `TIME_MARK_EXT1` (2). |
| `FLAGS_TIME_MARK_EDGE` | `0x0004` | Bit 2: 0 = rising, 1 = falling edge. |
| `FLAGS_CALIB_TTAG_VALID` | `0x0008` | Bit 3: `calibTtag` follows the data words. |
| `FLAGS_NUM_MEAS` / `FLAGS_NUM_MEAS_SHIFT` | `0xF800` / `11` | Bits 15..11: `numMeas`. |
| `esf_meas_datum::DATA_TYPE_MASK` | `0x3F` | 6-bit `dataType`. |

### Fields

| Offset | Field | Type | Description |
| --- | --- | --- | --- |
| 0 | `time_tag` | `uint32_t` | Time tag generated by the external sensor. |
| 4 | `flags` | `uint16_t` | `FLAGS_*` bits; `numMeas` is overwritten from `data.size()` on encode. |
| 6 | `id` | `uint16_t` | Data provider identification. |
| 8 + n·4 | `data` | `vector<esf_meas_datum, MaxData>` | Stored data words. |
| 8 + numMeas·4 | `calib_ttag` | `uint32_t` | Receiver local time calibrated [ms]; on the wire iff `calib_ttag_valid()`. |

### Functions

| Function | Description |
| --- | --- |
| `static bool matches(const message_view&)` | Class/ID check. |
| `static bool decode(const message_view&, esf_meas&)` | `numMeas != 0`: requires length `8 + numMeas·4 + (calibTtagValid ? 4 : 0)` exactly. `numMeas == 0`: count = `(length - 8 - (calibTtagValid ? 4 : 0)) / 4`, which must be a whole, non-negative number of words. `out` value-initialised on failure. |
| `void encode(payload_writer&) const` | Writes `numMeas = data.size()` into `flags`, then the stored words and, iff `calib_ttag_valid()`, `calib_ttag`. |
| `uint8_t time_mark_sent() const` | `flags` bits 1..0. |
| `bool time_mark_edge() const` | `flags` bit 2. |
| `bool calib_ttag_valid() const` | `flags` bit 3. |
| `uint8_t num_meas() const` | `flags` bits 15..11 as on the wire (0 = implied by length; may exceed `data.size()` after decode). Use `data.size()` for the stored count. |

## Usage Example

```cpp
// Host -> receiver: one speed sample (data type 11).
esf_meas<4U> input{};
input.time_tag = sensor_time_ms;
esf_meas_datum speed{};
speed.data_type = 11U;
speed.data_value = speed_mm_s;
static_cast<void>(input.data.push_back(speed));
castle::status result = encode_message(input, frame, sizeof(frame), written);
```

## Constraints & Notes

- Capacity: `MaxData` (≤ 31) words are stored; extra words on the wire are skipped and `calib_ttag` is still read.
- `encode()` latches `castle::status::out_of_range` (nothing is emitted) when a `data_value` is outside
  [-2^23, 2^23-1] or a `data_type` exceeds 63. Too small an output buffer gives `castle::status::full`.
- The spec says the receiver always sends `calibTtagValid = 0`; the optional field is supported for completeness.
- `numMeas` is "optional, can be obtained from message size" in the spec. A non-zero `numMeas` is authoritative and
  must match the length exactly; `numMeas == 0` means "infer from the length". An implied count may exceed 31;
  storage still clamps at `MaxData`. `encode()` always writes `numMeas = data.size()`, so encoded frames never
  rely on inference.
- Value type: every member lives in the object; no heap allocation, no exceptions.
- `message_view` is non-owning; its payload must stay valid while `decode()` runs.
- Thread-safety: none. Instances are plain values and are not thread-safe; synchronise externally when shared.
