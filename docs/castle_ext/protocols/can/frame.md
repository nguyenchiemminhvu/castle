# CAN Frame

## Overview

Defines a fixed-capacity value type for Classical CAN and CAN FD frames. It validates 11-bit and 29-bit identifiers, supported frame kinds, FD length codes, and control flags without allocation.

## Header

`#include "castle_ext/protocols/can/frame.hpp"`

## Public API

| API | Description |
|---|---|
| `identifier_format` | `standard` (11-bit / CAN 2.0A) or `extended` (29-bit / CAN 2.0B). |
| `frame_kind` | `data`, `remote`, `error`, and `overload`. |
| `frame_format` | `classical` or `fd`. |
| `frame::valid()` | Validates identifier, kind, format, flags, and byte length; O(1). |
| `frame::data_length_code()` | Returns DLC 0..15 or `0xFF` if invalid; O(1). |
| `is_valid_fd_data_length(length)` | Accepts 0..8, 12, 16, 20, 24, 32, 48, or 64 bytes. |
| `fd_data_length_code(length)` | Maps an FD byte length to its DLC or `0xFF`. |
| `make_data_frame(...)` | Builds and validates a data frame from a pointer/length pair or `castle::container::array_view`; O(length), output is unchanged on failure. |
| `make_remote_frame(...)` | Creates a Classical CAN remote frame with requested length 0..8. |
| `make_error_frame(...)` / `make_overload_frame(...)` | Creates controller-signaling event values. |

## Usage Example

```cpp
#include "castle_ext/protocols/can/frame.hpp"
#include <assert.h>

int main()
{
    using namespace castle::protocols::can;
    const uint8_t bytes[2] = {0x12U, 0x34U};
    frame value{};
    assert(castle::succeeded(make_data_frame(
        0x123U, identifier_format::standard, frame_format::classical,
        bytes, 2U, value)));
    assert(value.valid());
    assert(value.data_length_code() == 2U);
    return 0;
}
```

See [`samples/castle_ext/protocols/can/frame.cpp`](../../../../samples/castle_ext/protocols/can/frame.cpp).

## Constraints & Notes

- Storage is inline and always reserves 64 payload bytes per frame value.
- Classical frames carry at most 8 bytes. CAN FD accepts only DLC-representable byte counts (0..8, 12, 16, 20, 24, 32, 48, 64).
- CAN FD supports data frames only; remote, error, and overload frame kinds are Classical CAN only. In a real controller, error and overload signaling is generated by the CAN controller, not sent as application payloads.
- This is a protocol value model, not a hardware driver or a complete on-wire serializer.
