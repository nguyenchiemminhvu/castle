How to read this run

No reliable overall winner

Among the more plausible rows, CASTLE and STL are often close, with some operation-specific differences in both directions. This run is best treated as an initial signal, not as evidence that either implementation is universally faster.

  • CASTLE leadsThe visible results favor CASTLE for several hash/tree insert and erase cases, string search, array access, and bitset string conversion. These are individual results, not a general guarantee.
  • STL leadsThe visible results favor STL for string construction and substring search, and for the queue push/pop case. Other common operations are close in this run.
  • Mostly comparableMany measured operations show similar times, especially basic chrono, utility, and vector operations. Several displayed sub-nanosecond values are too close to the measurement floor for a confident ranking.

Measurement warning. Many rows report only one iteration alongside implausibly large elapsed times; the benchmark harness has timing-pause placement issues in affected cases. Some extremely small times are also vulnerable to optimizer elimination and timer resolution. Treat those rows as invalid for ranking. For a defensible comparison, rerun corrected benchmarks with observable results, repeated samples, and the intended target hardware.
