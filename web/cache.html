Cache

Fixed-capacity key/value caches with a compile-time eviction policy: FIFO, LIFO, LRU, MRU, and LFU over one shared engine.

#include "castle/cache/cache.hpp"

Overview

The castle/cache module provides bounded caches whose eviction policy is chosen at compile time. The basic_cache engine owns all entry storage and a chained hash index; each policy decides which entry leaves when a new key arrives in a full cache. No heap, exceptions, RTTI, or STL are used.

Dependencies

  • core/status.hpp for status codes returned by erase() and evict().

Eviction policies

PolicyUse whenEvicts when full
FIFOData is time-ordered and access does not matterEarliest inserted
LIFOEarly entries must stay resident; transient entries rotate above themMost recently inserted
LRURecently used entries are likely to be used againLeast recently used
MRURepeated sequential scans larger than the cacheMost recently used
LFULong-term popularity predicts future useLowest access count, LRU among ties

Public API

APIDescription
basic_cache<Key, T, N, Policy, Hash, KeyEqual>Engine shared by all aliases; capacity N is fixed at compile time.
fifo<Key, T, N>, lifo<Key, T, N>, lru<Key, T, N>, mru<Key, T, N>, lfu<Key, T, N>Policy aliases over basic_cache.
put(key, value)Insert, or update an existing key (counts as an access). Returns T&.
put(key, value, on_evict)Same as above; calls on_evict(const Key&, T&) on the victim before destruction.
get(key)Lookup that records an access. Returns T*, or nullptr on miss.
peek(key), contains(key)Lookup without changing eviction order.
erase(key)Remove without eviction callback. Returns status::ok or status::not_found.
evict(), evict(on_evict)Remove the next victim. Returns status::ok or status::empty.

Usage example

#include "castle/cache/cache.hpp"

castle::cache::lru<uint8_t, int32_t, 2U> recent;
recent.put(1U, 10);
recent.put(2U, 20);
recent.get(1U);     // key 1 becomes most recently used
recent.put(3U, 30); // evicts key 2

castle::cache::lfu<uint8_t, int32_t, 2U> popular;
popular.put(1U, 10);
popular.put(2U, 20);
popular.get(1U);    // count(1) = 2, count(2) = 1
popular.put(3U, 30, [](const uint8_t&, int32_t&) {
    // Receives key 2 before it is destroyed.
});

Constraints & notes

  • Capacity N is fixed; storage lives inside the object. No heap allocation.
  • Include a single policy header such as castle/cache/lru.hpp when compile-time dependency size matters.
  • Pointers from get(), peek(), and put() stay valid until that entry is erased, evicted, or the cache is cleared.
  • Eviction callbacks run before the victim is destroyed and must not modify the cache.
  • A value argument must not refer to an entry stored in the same cache.
  • Lookup, insert, erase, and evict are O(1) on average; worst case is O(N) when all keys share one bucket.
  • LFU ties break by recency, so eviction order is fully determined by the access sequence.
  • Non-copyable and non-movable. No internal synchronization; guard shared instances with an external lock.
