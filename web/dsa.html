Data Structures & Algorithms

Castle’s fixed-capacity sequences, maps, buffers, and strings, together with deterministic, STL-free generic algorithms for search, copy, transform, remove, sort, and ordered lookup.

#include "castle/dsa/containers.hpp"
#include "castle/dsa/algorithm.hpp"

Overview

The dsa/ module groups Castle’s data structures and the algorithms that operate on them. All types live in castle::dsa; the generic algorithms live directly in castle.

  • containers.hpp is an umbrella header that pulls the container family into one include. Use it when a translation unit needs several containers and convenience matters more than minimizing header fan-in.
  • algorithm.hpp provides common search, copy, transform, remove, sort, and ordered-lookup operations for Castle iterators and raw pointers without heap allocation or recursion-heavy implementations.

Algorithms

Dependencies of castle/dsa/algorithm.hpp: iterator/iterator.hpp, castle/utility/move.hpp, castle/utility/pair.hpp, castle/utility/swap.hpp.

Usage example

See samples/dsa/containers.cpp and samples/dsa/algorithm.cpp.

#include "castle/dsa/containers.hpp"
#include "castle/dsa/algorithm.hpp"

castle::dsa::array<int, 2U> values{1, 2};
castle::dsa::map<int, int, 2U> ordered;
ordered.insert(1, 10);

int raw[6] = {4, 1, 7, 1, 9, 2};
castle::sort(raw, raw + 6);

int* found = castle::find(raw, raw + 6, 7);
bool has_nine = castle::binary_search(raw, raw + 6, 9);

(void)found;
(void)has_nine;

Constraints & notes

  • No heap allocation, exceptions, RTTI, or STL containers/algorithms.
  • containers.hpp introduces no allocation behavior; it only aggregates other Castle headers. Prefer individual headers when compile time or preprocessing footprint matters.
  • Thread-safety depends entirely on the specific container types you use; no synchronization is added.
  • Iterator categories are checked with static_assert; unsupported iterator types fail at compile time.
  • sort() uses iterative heapsort, not quicksort or mergesort.
  • remove, remove_if, and unique do not resize containers; callers must treat the returned iterator as the new logical end.
  • Ordered lookup assumes the range is already sorted with the same comparator.
